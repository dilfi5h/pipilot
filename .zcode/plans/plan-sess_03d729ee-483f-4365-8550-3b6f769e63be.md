# 修复会话列表为空问题 — 实施计划

## 问题结论（已定位）
`PiViewModel.listSessions()`（`PiViewModel.kt:500-531`）经 `SshConnector.runQuick` 在远端执行了一条强依赖 GNU `find -printf` 的 shell，且路径写死为 `~/.pi/agent/sessions`。两处任一命中即静默返回空列表（`2>/dev/null` 把报错吞掉，`AppLog` 只记 `listSessions -> 0 files`），UI（`PiScreen.kt:719-721`）又把“加载中”和“真的没有”都渲染成同一句“没有找到”，打开瞬间必现空列表。

按可能性排序的根因：
1. **GNU 扩展 `find -printf '%T@ %p'` 不可移植** — 远端若是 BusyBox / Alpine / macOS BSD find，该选项直接报错退出，管道后全空。这是最可能的致空点。
2. **会话目录写死** — 上游支持 `PI_CODING_AGENT_DIR` / `PI_CODING_AGENT_SESSION_DIR` / `--session-dir` 覆盖（见 `vendor/pi-upstream/.../config.ts:528-577`、`session-manager.ts:474-490`），且 `~` 按 SSH 登录用户展开，与 `pi --mode rpc` 进程的 HOME 不一致即 miss。
3. **UI 无 loading 态 + 先弹 sheet 后异步回填**（`PiScreen.kt:122`），正常加载中也会闪一下“没有找到”，与真空无法区分。

## 改动方案
### 1. `PiViewModel.kt::listSessions()` — 换可移植命令 + 动态目录（核心修复）
- 新 shell 逻辑（POSIX `find` + `ls -t` 排序，全平台可用）：
  ```sh
  agentdir=${PI_CODING_AGENT_DIR:-$HOME/.pi/agent}
  sessdir=${PI_CODING_AGENT_SESSION_DIR:-$agentdir/sessions}
  find "$sessdir" -type f -name '*.jsonl' -exec ls -t {} + 2>/dev/null | head -30 | while IFS= read -r p; do
    n=$(grep -h '"type":"session_info"' "$p" 2>/dev/null | tail -1 | sed -n 's/.*"name":"\([^"]*\)".*/\1/p')
    printf '%s\t%s\n' "$p" "$n"
  done
  ```
- 要点：用 `$HOME` 代替裸 `~`；`ls -t` 代替 `-printf+sort` 做 mtime 排序；保留现有 `path\tname` 输出协议与 Kotlin 解析逻辑（`substringBefore('\t')` 等）不变，降低回归面。
- 兜底：若 `$sessdir` 不存在/结果为空，再试一次当前 `state.sessionFile` 所在父目录（从 `get_state` 已知的 `sessionFile` 推导），覆盖 `--session-dir` 自定义场景；两次结果合并去重。
- 日志加强：`AppLog` 多记一行实际使用的 `sessdir` 与原始输出行数，方便设置页日志定位。

### 2. `PiViewModel.kt::UiState` + `PiScreen.kt::SessionsSheet` — 区分加载中/空
- `UiState` 新增 `sessionsLoading: Boolean = false`；`listSessions()` 进入置 true、结束置 false（成功/失败都复位）。
- `SessionsSheet`：`sessionsLoading` 为 true 时显示 `CircularProgressIndicator + "正在列出会话…"`；仅当 `!loading && sessions.isEmpty()` 才显示空文案，并把文案改为带实际路径的提示（如“在 <sessdir> 下没有找到会话”），避免误导。

### 3. 不改（刻意保持最小）
- 触发时机保持手动点击（`PiScreen.kt:122`）不变，不引入 onResume 自动刷新。
- `switchSession` / `deleteSession` / `refreshAll` 不动；`grep session_info + sed 取名` 逻辑不动（取不到仅回退文件名，不致空）。

## 验证
1. 编译：`./gradlew :app:assembleDebug`。
2. 真机验证：连上后打开会话列表，分别确认有会话时列出、无会话时提示、日志中有 `listSessions -> N files` 与 sessdir 行；另在远端手动跑新旧两条命令对比输出，确认旧命令空、新命令有结果（或反之定位到目录问题）。
3. 回归：切换会话、长按删除、重连恢复 `--session` 行为不变。

## 风险
- `find ... -exec ls -t {} +` 在超大目录下由 `ls` 排序，开销与旧方案相当（旧方案还逐文件 grep），30 个截断保持不变。
- 路径含换行符的极端情况仍按行切分，与现有行为一致，不扩大处理范围。
